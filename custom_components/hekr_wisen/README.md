# Hekr / Wisen (KKT Kolbe) — Home Assistant integration

> *Generated by [aurora@aurora-smart-home (ha-integration-dev skill)](https://github.com/tonylofgren/aurora-smart-home)*

Custom integration for devices on the **Hekr / Wisen** IoT cloud platform —
the cloud behind the **Wisen App**. The reference device is the **KKT Kolbe**
range hood (older models used this cloud connection; tested target:
**SOLO807SM**, model **M002**), but other Hekr/Wisen device types can be added.
Ported from the [`ioBroker.hekr`](https://github.com/TA2k/ioBroker.hekr) adapter
by TA2k (MIT License).

## What this does

- Logs in to the Hekr/Wisen cloud with your app **email + password**.
- Discovers your hood(s) and opens the cloud **WebSocket** for live status.
- Exposes the hood as Home Assistant entities:

| Entity | Platform | Source field / command |
|---|---|---|
| Fan (off, speed 1–4) | `fan` | `speed` / `Set_Speed` |
| Power | `switch` | `sw` / `set_Sw` |
| Spotlight | `light` (on/off) | `light_Sw` / `set_LightSw` |
| RGB light | `light` (rgb) | `RGB_Sw,R,G,B` / `set_Rgbw` |
| Filter change | `binary_sensor` (problem) | `fitter` |
| Reset filter reminder | `button` | `rest_Cleaning` |
| Auto-off timer (1–60 min) | `number` | `tm_Minutes` / `set_Tm` |
| Operating state | `sensor` (diagnostic) | `Statue` |

**Status** always arrives through the cloud WebSocket. **Commands** go through
the cloud by default, or — if you enable it — directly to the hood over the LAN
(UDP port 10000). The device keys (`devTid`, `ctrlKey`, `lanIp`) are cached in
the config entry so local commands keep working without re-querying the cloud.

## Installation (Home Assistant Container / Docker, no Supervisor)

> **Via HACS:** add `https://github.com/FDC4000/HA.hekr` as a custom repository
> (type *Integration*), download **Hekr / Wisen**, restart, then add the
> integration. See the [repository README](../../README.md#installation) for
> the full HACS steps. The manual steps below are the alternative.

1. Copy the integration into your config folder so you end up with:

   ```
   /config/custom_components/hekr_wisen/
   ```

   With a typical Docker setup (host path mapped to `/config`):

   ```bash
   cp -r custom_components/hekr_wisen \
     /path/to/your/ha-config/custom_components/
   ```

   If `custom_components/` does not exist yet, create it first.

2. Restart the container:

   ```bash
   docker restart homeassistant
   ```

3. In HA go to **Settings → Devices & Services → + Add Integration**, search for
   **Hekr / Wisen**, and sign in with your Wisen app **email and password**.

## Configuration

After setup, open the integration's **Configure** dialog for options:

- **Use local UDP control** — send commands to the hood's LAN IP (UDP 10000)
  instead of via the cloud. Status still comes from the cloud.
- **Frame checksum mode**
  - **Calculated (correct)** — `sum(bytes) & 0xFF`, per the official Hekr SDK
    (default, recommended).
  - **Zero (original adapter)** — trailing `0x00`, exactly as the original
    ioBroker adapter. Only for debugging if the calculated frames are rejected.

## Troubleshooting / debugging against the real hood

Enable debug logging in `configuration.yaml`:

```yaml
logger:
  default: info
  logs:
    custom_components.hekr_wisen: debug
```

Then restart and watch the log. Useful signals:

- `Login successful` / `Fetched N device(s)` — cloud auth and discovery work.
- `WebSocket connected and appLogin sent` — live status channel is up.
- Entities show **unavailable** → the WebSocket is not connected (the hood may
  be offline/powered off; it must have mains power and Wi-Fi).

Download **Settings → Devices & Services → Hekr / Wisen → ⋮ → Download diagnostics**
to inspect state. All secrets (password, tokens, `ctrlKey`, product key, LAN IP)
are redacted.

### Local UDP control and checksum

Verified on real hardware (2026-11-14): with **Use local UDP control** enabled and
checksum mode **Calculated**, a command sent to the hood's LAN IP on UDP port
10000 is executed and reflected almost immediately — notably faster than the
cloud path, with no `uart timeout` delay. The device validates the checksum on
the LAN (the cloud re-signs it, so the original adapter's hard-coded `00` only
works via the cloud). Therefore keep checksum mode on **Calculated** for local
control; **Zero** is cloud-only and for debugging. Local UDP requires Home
Assistant to be on the same subnet as the hood.

### Commands are slow / `uart timeout` in the log

Confirmed on real hardware: a command can take noticeably long to take effect,
and the cloud often returns `appSendResp code 2000105 "uart timeout"` **even when
the command actually succeeds** — the hood's controller acknowledges slowly. The
integration does not treat this as an error: it sends the frame and waits for the
device's own status push (`devSend`), so the matching entity may update a few
seconds after you act. A command sent while the hood's controller is asleep
(Wi-Fi `online` but no recent activity) may be dropped — operate the hood once to
wake it.

### Known limitations / open points

- **RGB frame varies by model.** M002 sends `[RGB_Sw, R, G, B]`; some M001
  variants expect only `[R, G, B]`. The integration picks the layout from the
  reported `model`. If your RGB light misbehaves, note your model.
- **Colour wheel saturation.** The device takes raw R/G/B, so only the
  fully-saturated **outer rim** of Home Assistant's colour wheel produces pure
  colours; dragging toward the centre mixes in white (most visible on red,
  which washes out to pink). Pick the hue at the rim and use the separate
  **brightness** slider to dim — this keeps the colour pure instead of
  desaturating it.
- **Filter reset value is unverified.** Per TA2k's README, writing `cleaning`
  to `0` clears the reminder; the button uses `0`. If your hood needs `1`,
  change `_RESET_VALUE` in `button.py`.
- **No purely local status.** Local UDP carries commands only; status needs the
  cloud WebSocket (same as the original adapter).

## Recovery

- **Wrong password / token rejected:** HA shows a reauth prompt — re-enter the
  password. No need to delete the integration.
- **Start over:** remove the integration in **Devices & Services**, then re-add.
- **Remove entirely:** delete `/config/custom_components/hekr_wisen/` and restart.
